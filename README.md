# Code Assistant

OpenAI Codex로 코드 어시스턴트를 만들며, 소스 탐색부터 변경 검증까지의 과정을 실험하는 저장소입니다. 인프런 강의에서 다루는 Claude Code의 에이전트 설계를 출발점으로 삼고, 각 실습을 Codex 환경에 맞춰 구현합니다.

## 어떤 문제를 풀고 싶은가

코드 리뷰에서 “테스트가 통과했다”는 설명을 받으면, 어떤 테스트를 실행했고 그 테스트가 변경한 동작을 검증하는지 확인하게 됩니다. 코드 어시스턴트에도 같은 기준을 적용하고 싶습니다. 기능 변경을 맡겼을 때 Codex가 기존 호출부를 찾고, 수정 범위를 정하고, 변경이 의도대로 동작한다는 근거를 남기도록 개발 환경을 설계합니다.

이 프로젝트의 실험 대상은 **에이전트 하네스(agent harness)**입니다. Codex에 제공할 프로젝트 지침, 파일과 명령에 대한 접근 권한, 결과를 확인하는 테스트 절차가 여기에 해당합니다. 같은 과제를 다시 실행하면서 각 설정이 코드 변경과 검증 과정에 어떤 차이를 만드는지 살펴봅니다.

## 실습 로드맵

| 주제 | 실습할 내용 | 확인할 항목 |
| --- | --- | --- |
| 프로젝트 컨텍스트 | 빌드 명령과 테스트 규칙을 `AGENTS.md`에 정리하고 같은 변경을 다시 요청합니다. | 올바른 테스트를 선택했는지, 실행 명령을 다시 알려줘야 했는지 |
| 실행 권한과 샌드박스 | 읽기 전용 코드 리뷰와 파일 수정 작업에 서로 다른 권한을 적용합니다. | 각 작업에서 허용된 파일 변경과 승인이 필요한 명령 |
| 변경 검증 | 버그를 재현하는 테스트를 만든 뒤 Codex에 수정을 맡깁니다. | 같은 테스트가 수정 전에는 실패하고 수정 후에는 통과하는지 |
| 구현과 리뷰 분리 | 같은 변경을 구현 세션과 별도의 리뷰 세션에서 각각 검토합니다. | 각 세션이 발견한 경계 조건과 테스트로 재현할 수 있는 결함 |

## 실험 기록 방식

한 번의 실습에서는 하나의 설정을 바꿉니다. 예를 들어 프로젝트 지침의 효과를 확인할 때는 같은 기준 커밋에서 새 세션 두 개를 시작하고, 한쪽에만 테스트 규칙을 제공한 뒤 동일한 기능 변경을 요청합니다. 두 실행의 `git diff`, 실제 테스트 명령, 종료 코드, 추가로 필요했던 지시를 함께 기록합니다. 이후 실습에서는 이 기록을 근거로 유지할 설정과 다시 검증할 조건을 정합니다.
