# Code Assistant

OpenAI Codex 기반의 코드 어시스턴트를 만들어 가는 개인 학습 프로젝트입니다. 인프런 강의에서 Claude Code로 다루는 에이전트 설계 원리를 배우고, 각 섹션의 실습을 Codex 환경에 맞게 적용합니다.

## 어떤 문제를 풀고 싶은가

**AI 에이전트로 개발자의 의도에 맞는 코드를 작성하고, 90~100점 수준의 결과물을 빠르게 만들어 내려면 무엇을 설계해야 할까?**

기능 하나를 맡겨도 기대하는 결과에는 여러 조건이 담겨 있습니다. 예를 들어 “주문 취소 기능을 추가해 줘”라는 요청에는 어떤 주문 상태에서 취소를 허용할지, 중복 요청은 어떻게 처리할지, 기존 결제 API의 응답 형식은 유지할지 같은 결정이 따릅니다. 이런 조건을 구현 후에야 전달하면 첫 코드가 아무리 빨리 나와도 리뷰와 재작업에 시간이 듭니다.

이 프로젝트에서는 개발자의 의도를 **요구사항·변경 범위·완료 조건**으로 명시하고, Codex가 그 기준에 따라 계획을 세우고 코드를 작성하도록 합니다. 반복해서 지켜야 할 규칙은 프로젝트 지침에 담고, 결과물은 테스트와 독립적인 리뷰로 검증합니다. 목표는 요청을 다시 설명하고 코드를 고치는 횟수를 줄여, **요구사항을 충족한 코드가 완성되기까지의 시간**을 단축하는 것입니다.

## 학습 로드맵

강의의 10개 섹션을 수강 순서대로 정리했습니다. 강의에서 다루는 `CLAUDE.md`의 역할은 이 프로젝트에서 Codex의 `AGENTS.md`에 대응시켜 학습합니다.

| 섹션 | 학습 주제 | 주요 내용 |
| --- | --- | --- |
| 1 | 강의 소개 | 강의 목표와 전체 학습 흐름을 파악합니다. |
| 2 | 에이전트 초기 설정 | 실습 폴더에서 첫 요청을 실행하고, 지침이 없는 상태의 동작을 살펴봅니다. Git 체크포인트를 만들어 변경을 되돌려 봅니다. |
| 3 | 프로젝트 지침과 컨텍스트 | 기대하는 결과물에서 출발해 지침을 작성합니다. 지침의 적용 순서, 컨텍스트와 메모리의 관계, 지침 길이에 따른 토큰 사용량을 살펴봅니다. |
| 4 | 결과물의 품질을 높이는 요청 패턴 | 요청서에 수정 범위를 명시하고 계획 수립·승인·실행을 분리합니다. 작업 단위를 나눠 실패의 영향을 줄이는 방법을 익힙니다. |
| 5 | 토큰 비용과 캐시 최적화 | 대화가 누적될 때의 토큰 비용을 살펴보고, 대화 압축·초기화, 출력 길이 조절, 캐시 활용 방법을 배웁니다. |
| 6 | 하네스와 검증 자동화 | 훅(Hook)으로 검증 절차를 자동화하고, 검증 결과에 따라 재시도하거나 실행을 차단하고 알림을 보내는 흐름을 구성합니다. |
| 7 | 실행 권한과 외부 입력 방어 | 허용·거부 목록과 샌드박스로 실행 범위를 제한합니다. 조직과 프로젝트의 지침 적용 범위를 구분하고, 외부 콘텐츠에 포함된 프롬프트 주입에 대비하는 입력 검증을 다룹니다. |
| 8 | 서브에이전트와 자기 선호 편향 | 테스트를 먼저 작성하고, 별도 에이전트가 구현 결과를 검토하도록 역할을 분리합니다. 서브에이전트 수와 모델 선택에 따른 검토 효과와 토큰 비용을 살펴봅니다. |
| 9 | 멀티에이전트 협업과 작업 예약 | 에이전트를 순차 호출해 기능을 구현하고, 비잔틴 장애 허용(BFT)의 합의 관점에서 병렬 검토 결과를 다루는 패턴을 배웁니다. 세션 간 통신과 정기 작업 예약도 다룹니다. |
| 10 | 스킬과 플러그인 패키징 | 반복 작업을 재사용할 수 있는 스킬(Skill)로 정의하고, 이를 플러그인으로 묶어 적용하는 과정을 익힙니다. |
